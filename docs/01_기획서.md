## 2. 배경 및 목적

하드디스크·SSD는 고장 나기 전에 **SMART(Self-Monitoring, Analysis and Reporting Technology)** 라는 자가 진단 수치를 남긴다. 배드섹터 수, 재할당 섹터 수, 가동 시간, 온도 등이다.

이 수치의 변화 패턴을 머신러닝으로 학습하면, **디스크가 완전히 죽기 전에 "곧 고장날 위험이 높다"를 미리 예측**할 수 있다. PDFS는 이 예측을 실시간으로 제공하는 것을 목표로 한다.

---

## 3. 예측 범위 (결정됨)

| 대상 | 데이터 상황 | 결정 |
|------|------------|------|
| **HDD/SSD** | Backblaze Drive Stats — 공개·풍부, 예제 다수 | ✅ **핵심 범위** |
| RAM | 공개 데이터 부족(대회용 1개), 시스템 로그 기반으로 난이도 높음 | ⏸ **확장 과제** (시간 남으면) |
| 통합 "어느 부품?" 예측 | HDD와 RAM 데이터 형식이 달라 통합 데이터셋 없음 | ❌ 현 단계 제외 |

> **결정 근거:** ML 프로젝트의 성패는 데이터 확보에 달려 있다. HDD/SSD는 Backblaze 데이터가 잘 정리돼 있어 현실적으로 결과를 낼 수 있다. RAM은 학술 연구 수준 난이도라 후속 과제로 분리했다. 발표 시 "RAM은 데이터 한계로 후속 과제로 설계"는 현실 판단력으로 어필 가능.

---

## 4. 동작 형태 (결정됨)

**실시간 모니터링형(B) + 데모 시뮬레이션 모드(C)** 조합.

| 모드 | 설명 |
|------|------|
| 평상시 (실시간) | PC에 설치한 에이전트가 SMART를 수집 → 서버 전송 → 대시보드에 실시간 상태·위험도 표시 |
| 발표용 (데모) | Backblaze의 "고장 직전 디스크" 데이터를 주입 → 위험 알림이 뜨는 과정을 시연 |

> **왜 데모 모드가 필요한가:** 실시간 모니터링만 하면, 시연하는 순간에 팀원 PC 디스크가 고장나 주지 않는다. 정상 디스크는 "위험 없음"만 표시되어 발표가 밋밋해진다. 핵심인 "고장 예측"을 보여주려면 고장 데이터를 주입하는 데모 모드가 필수다.

---

## 5. 시스템 구조 초안

```
[에이전트]        → SMART 수집 (smartctl 등)        ← 인프라(안세웅) + 백엔드
   ↓ 전송
[수집 서버 API]   → 데이터 수신·저장                ← 백엔드(이성룡·홍제규)
   ↓
[PostgreSQL]     → SMART 이력 저장
   ↓
[ML 예측 서비스]  → 고장 위험도 추론                ← 데이터 분석(김응석)
   ↓
[대시보드]       → 실시간 상태·위험 알림            ← 프론트(장영재)
   +
[데모 모드]      → Backblaze 고장 데이터 주입        ← 인프라(안세웅)
```

> 수집 → 처리 → 알림으로 이어지는 흐름. (참고: 동일 패턴의 SafeAlert 프로젝트 경험 활용 가능)
