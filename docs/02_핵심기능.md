# PDFS 핵심 기능 정의 (MVP)

## 1. MVP 범위

초보 팀일수록 범위를 작게 잡고 끝까지 완성하는 것이 성공 비결이다.
아래 **필수 기능 8개(F-01~F-08)** 만 먼저 완성한다. 이것만으로 "실시간 고장 예측 → 조치 → 완료"라는 완결된 프로젝트가 된다.

확장 기능(로그인, 여러 디스크 관리, 알림 이력, RAM 예측 등)은 MVP가 돌아간 뒤에 검토한다.

## 3. 기능별 상세

### F-01. 고장 예측 모델 학습
- Backblaze Drive Stats 데이터로 "고장/정상"을 예측하는 모델을 만든다.
- 핵심 SMART 항목 선택 사용 (실제 코드 기준 10개: model·capacity + smart 5·9·187·188·194·197·198·199 — [03_데이터확인.md](03_데이터확인.md) 3-1 참고).
- 모델은 **GradientBoosting** 사용 (7개 모델 비교 후 확정 — 상세 근거는 [03_데이터확인.md](03_데이터확인.md) 참고). 트리 기반 앙상블이라 표 데이터에 강하고 해석 가능.
- ML 단독이 아니라 **ML + 규칙 기반 하이브리드 판정**으로 Recall(고장 놓침)을 보완한다 (03 4-5 참고).
- ⚠️ 데이터 불균형 주의: 고장 디스크는 전체의 약 0.006%(실측). 정확도(accuracy) 대신 **Recall(고장을 놓치지 않은 비율)** 을 핵심 지표로 본다.

### F-02. 예측 API (모델 서빙)
- 학습한 모델을 API로 감싸 외부에서 호출 가능하게 한다 (예: Python FastAPI).
- 입력: SMART 값 → 출력: 고장 위험도(점수 또는 위험/정상).

### F-03. SMART 수집 에이전트
- PC에 설치되어 디스크 SMART 값을 주기적으로 읽어 서버로 전송한다.
- smartctl(smartmontools) 등 활용. OS별 출력 차이 처리 필요.
- ⚠️ 학습 데이터(Backblaze)와 컬럼·단위를 일치시키는 매핑 작업 필요.

### F-04. 수집 데이터 저장·조회 API
- 에이전트가 보낸 SMART 데이터를 받아 DB에 저장하고, 대시보드가 조회할 수 있게 제공한다.

### F-05. 실시간 대시보드
- 디스크별 현재 상태와 고장 위험도를 화면에 표시한다.
- 위험도에 따라 색상/단계 구분.

### F-06. 위험 알림
- 예측 위험도가 기준을 넘으면 사용자에게 경고를 표시한다.

### F-07. 데모 모드
- 발표용. Backblaze의 "고장 직전 디스크" 데이터를 주입해 위험 알림이 뜨는 과정을 시연한다.
- 실시간 모니터링만으로는 시연 중 고장이 발생하지 않으므로 필수.

### F-08. 조치 상태 관리
- 위험/주의 디스크의 대응 상태를 관리한다: **미확인 → 확인됨 → 조치 완료**.
- "확인" = 담당자가 인지(알림 진정). "조치 완료" = 백업·교체 완료 → 위험 목록에서 해제, 해결됨 처리.
- "감지 → 조치 → 완료"의 루프를 닫아 제품을 완결한다. (조치 이력 로그는 확장 과제)

## 4. ML 5단계 ↔ 기능 매핑

```
① 데이터 수집   → F-03, F-04
② 데이터 전처리 → F-01
③ 모델 학습     → F-01
④ 평가          → F-01
⑤ 서빙          → F-02, F-04, F-05, F-06, F-07, F-08
```

> ⑤서빙 단계에서 5명 전원의 작업이 만난다 (모델 API · 데이터 연동 · 화면 · 배포).

---

## 5. 목표 눈높이

- 목표는 "완벽한 예측"이 아니라 **"고장 위험을 미리 경고"** 다.
- 모델 성능은 데이터·전처리에 따라 초기엔 기대보다 낮을 수 있다. 팀 전체가 이 눈높이를 공유한다.
