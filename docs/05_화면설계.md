# PDFS 화면 설계

> 현업 모니터링 시스템의 정보 위계를 따른 화면 구성
> 작성일: 2026-06-02 · 상태: 화면 구성 확정안
> 관련 문서: [02_핵심기능.md](02_핵심기능.md) · [03_데이터확인.md](03_데이터확인.md)

---

## 1. 설계 원칙 (기반)

PDFS는 "장비 상태를 모니터링하고 고장을 예측하는 시스템"으로, 현업 관제 대시보드(Grafana·Datadog 등)와 같은 부류다. 이들이 공통으로 따르는 3원칙을 화면 설계의 기반으로 삼는다.

| 원칙 | 뜻 | PDFS 적용 |
|------|-----|----------|
| ① 정보 3단계 깊이 | 요약 → 목록 → 상세로 파고듦(drill-down) | 전체 숫자 → 위험 디스크 목록 → 디스크 진단 |
| ② 위험 우선 노출 | 정상은 조용히, 위험은 눈에 띄게 | 위험 디스크를 색·정렬로 상단에 |
| ③ 추세를 보여주기 | 시간에 따른 악화 흐름 표시 | SMART 시계열 차트로 "왜 위험한지" 설득 |

---

## 2. 화면 목록

| 화면 | 경로(예시) | 목적 | 우선순위 | 기능 |
|------|-----------|------|:---:|------|
| 메인 대시보드 | `/` | 전체 상태 한눈에 + 위험 강조 | 🔴 필수 | F-05, F-06 |
| 디스크 상세 | `/disks/{serial}` | 개별 SMART 추이·예측 근거 | 🔴 필수 | F-05 |
| 데모 제어 | 대시보드 내 패널 | 고장 데이터 주입 시연 | 🔴 필수 | F-07 |
| 알림 이력 | `/alerts` | 과거 위험 이벤트 로그 | 🟡 여유 시 | (확장) |

> **로그인: 미적용.** 데모 중심 프로젝트이므로 인증은 넣지 않는다. (필요 시 확장 과제)

## 3. 화면별 상세

### 3-1. 메인 대시보드 (`/`) — 가장 중요

```
[상단 요약 카드]
  전체 N개 · 정상 N · 주의 N · 🔴 위험 N

[위험 디스크 섹션]
  위험도 높은 순으로 상단 정렬, 색상 강조
  (디스크명 · 위험도 · 핵심 SMART 요약)

[전체 디스크 목록/그리드]
  상태별 색상 (정상=초록 / 주의=노랑 / 위험=빨강)
  클릭 시 → 디스크 상세로 이동

[실시간 갱신 표시]
  ● 업데이트 중 (주기적 갱신)

[데모 제어 패널]  ← 3-3 참고
```

- 원칙 ①요약 + ②위험 우선 적용. "한눈에 보고 문제를 즉시 발견"이 목적.
- 디스크 항목 클릭 → 상세 화면으로 drill-down.

### 3-2. 디스크 상세 (`/disks/{serial}`)

```
[디스크 정보]
  모델 · 시리얼 번호 · 용량

[현재 위험도]
  게이지 또는 등급 표시 (정상 / 주의 / 위험)

[SMART 추이 차트]
  핵심 SMART(5, 187, 188, 197, 198) 시계열 그래프
  → 시간에 따라 값이 나빠지는 흐름

[예측 결과]
  "고장 위험 높음" 등 등급 + 근거가 된 SMART 값 강조

[조치 액션]  ← F-08
  현재 조치 상태 (미확인 / 확인됨 / 조치완료)
  [확인] [조치 완료] 버튼
```

- 원칙 ③추세 적용. **예측의 설득력**이 이 화면에서 나온다.
- 조치 상태 관리는 8번 참고.

### 3-3. 데모 제어 (대시보드 내 패널)

```
[데모 시작 버튼]
  → Backblaze "고장 직전 디스크" 데이터 주입
  → 대시보드에 위험 알림이 뜨는 과정을 실시간 시연
```

- F-07. 별도 페이지가 아닌 대시보드 내 버튼/패널로 가볍게 구성.
- 발표 시연의 핵심.

### 3-4. 알림 이력 (`/alerts`) — 여유 시

```
[위험 이벤트 목록]
  발생 시각 · 디스크 · 위험도 · 상태
```

- 과거에 위험으로 분류된 이벤트 로그. MVP 완성 후 추가.

## 4. 화면 흐름 (네비게이션)

```
메인 대시보드 (전체 현황)
   │  디스크 클릭
   ▼
디스크 상세 (개별 진단)

메인 대시보드
   │  데모 시작 버튼
   ▼
위험 알림 시연 (대시보드 내)
```

→ "전체 보기 → 파고들기 → 시연"이라는 현업 관제 흐름을 그대로 따른다.

---

## 5. 현업 근거 (면접 어필 포인트)

- **Overview → Detail drill-down**은 모든 관제 시스템의 표준 정보 위계.
- **위험 우선 노출**은 운영자가 문제를 빨리 찾게 하는 UX 원칙.
- **시계열 추세 표시**는 단순 현재값이 아닌 "악화 패턴"을 보여줘 예측 서비스다움을 살린다.
- 화면 수는 적지만(필수 3개), 현업 모니터링의 핵심 흐름을 모두 갖춘 구성이다.

## 7. 화면 흐름 (사용 시나리오)

팀원들이 "이 화면들을 실제로 어떻게 쓰는지" 이해하기 위한 흐름이다.

### 7-1. 평상시 사용 흐름 (운영자가 모니터링)

```
1. 대시보드 접속
   → 전체 디스크 현황을 한눈에 본다 (정상 20 · 주의 3 · 위험 1)

2. 시스템 분석 차트 확인
   → 위험 디스크가 늘어나는 추세인지 파악

3. "주의가 필요한 디스크"에서 위험 디스크 발견
   → ZA12B9KL 고장 위험도 92% 확인

4. 해당 디스크 클릭 → 디스크 상세로 이동

5. 상세에서 진단
   → 위험도 게이지(92%) · SMART 30일 추이(악화 중) · 예측 근거 확인

6. 권장 조치 확인
   → "데이터 백업 후 교체" → 실제 대응
```

### 7-2. 데모 시연 흐름 (발표용)

```
1. 대시보드의 "고장 시나리오 주입" 버튼 클릭
       ↓ (백엔드가 Backblaze 고장 직전 데이터 주입)
2. ML 예측 서비스가 "고장 위험 92%" 판정
       ↓
3. 우측 상단에 위험 알림 팝업 슬라이드인 ⚠
       ↓ ("상세 보기" 클릭)
4. 디스크 상세로 이동
       ↓
5. SMART 추이 그래프가 악화되는 모습 + 예측 근거 시연
```

> 데모의 하이라이트는 3번(알림 팝업 등장) — "실시간 예측이 작동한다"를 보여주는 장면이다.

### 7-3. 흐름에서 각 역할의 작업이 작동하는 지점

| 흐름 단계 | 작동하는 작업 | 담당 |
|-----------|--------------|------|
| 디스크 데이터 수집 | SMART 수집 에이전트 (F-03) | 인프라·백엔드 |
| 데이터 저장·조회 | 저장·조회 API (F-04) | 백엔드 |
| 고장 위험도 판정 | 예측 모델·API (F-01·F-02) | 데이터분석 |
| 대시보드·상세·알림 표시 | 화면 (F-05·F-06) | 프론트 |
| 데모 데이터 주입 | 데모 모드 (F-07) | 인프라 |

> 한 번의 사용 흐름에 5명 전원의 작업이 순서대로 맞물린다.

## 8. 조치 라이프사이클 (F-08)

"감지 → 조치 → 완료"의 루프를 닫아 제품을 완결한다. 디스크/알림의 대응 상태를 다음처럼 관리한다.

```
🔴 미확인        →   👀 확인됨           →   ✅ 조치 완료
(위험 감지됨)        (담당자가 인지)          (백업·교체 완료)
   │                    │                       │
알림 팝업·위험목록    알림 진정,             위험 목록에서 해제,
   에 표시            "확인됨" 표시          "해결됨" 처리
```

| 상태 | 트리거 | 화면 변화 |
|------|--------|-----------|
| 미확인 | 모델/규칙이 위험·주의 판정 | 알림 팝업 + 위험 목록에 표시 |
| 확인됨 | 운영자가 **[확인]** 클릭 | 알림 진정, 상태 뱃지 "확인됨" |
| 조치 완료 | 운영자가 **[조치 완료]** 클릭 | 위험 목록에서 해제, "해결됨" 처리 |

- 버튼 위치: 디스크 상세 화면의 "조치 액션" 영역 (3-2 참고).
- 조치 완료된 디스크가 교체되면, 새 디스크가 다시 정상으로 모니터링된다.
- 조치 이력 로그(언제 누가 무슨 조치)는 확장 과제.
- 담당: 프론트(버튼·상태 표시) + 백엔드(상태 저장).
