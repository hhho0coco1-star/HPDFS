## 0. 선정 기준

- "멋진 기술"이 아니라 **"PDFS에 꼭 필요한가"** 를 기준으로 선정.
- 개인 프로젝트(SafeAlert)와 기술이 겹쳐도 무방하다. 꼭 필요하면 쓴다.
- **실제 구현(`app_pdfs_mockup_v3.py`)을 기준으로 확정.** 계획과 달라진 부분은 이유를 함께 기록한다.

## 1. 확정 기술 스택 (실제 구현 기준)

| 영역 | 기술 | 담당 기능 |
|------|------|-----------|
| ML 학습 | Python · pandas · scikit-learn | F-01 모델 학습·평가 |
| 모델 저장/로드 | joblib | `.pkl` 파일로 저장 → 앱에서 직접 로드 |
| 웹 앱 프레임워크 | **Streamlit** | 대시보드·자동진단·수동진단·상세·성능 화면 전체 |
| SMART 수집 | smartmontools (`smartctl`) | F-03 디스크 자동진단 (로컬 실행) |
| 데이터 저장 | CSV 로그 (`logs/`) | 진단 이력 누적 저장 |
| 상태 관리 | Streamlit `session_state` | 진단 결과·디스크 목록 화면 간 공유 |
| 실행 자동화 | `.bat` 스크립트 | 관리자 권한 실행·의존성 설치 자동화 |

> **핵심 결정:** 별도 백엔드 서버 없이 Streamlit 단일 앱으로 통합. ML 모델은 FastAPI 서빙 대신 joblib로 앱 내 직접 로드. DB는 PostgreSQL 대신 CSV 로그 파일.

---

## 2. 왜 Streamlit 단일 앱인가

| 비교 항목 | 초기 계획 (Spring Boot + FastAPI + React) | 실제 채택 (Streamlit) |
|-----------|-------------------------------------------|-----------------------|
| 개발 속도 | 서비스 3개 연동·통합 필요 | Python 파일 1개로 완결 |
| 팀 학습 비용 | Spring Boot·React 학습 필요 | Python 집중 |
| ML 모델 연동 | FastAPI 별도 서버·HTTP 통신 | joblib 직접 로드, 지연 없음 |
| 포트폴리오 가치 | 기술 수 많음 | ML 파이프라인 완성도로 어필 |
| 4주 완성 현실성 | 위험 | ✅ 검증됨 |

> Streamlit은 "데이터 과학·ML 결과를 빠르게 웹으로 보여주는" 프레임워크로, PDFS처럼 **ML이 핵심인 프로젝트에 적합**하다.

## 3. 구성 요소별 파일 구조

```
HPDFS_release/
├── app_pdfs_mockup_v3.py     ← Streamlit 앱 (전체 화면·로직)
├── models/
│   └── storage_best_model.pkl  ← 학습된 GradientBoosting 모델
├── scores/
│   └── storage_model_scores.csv  ← 7개 모델 비교 결과
├── logs/
│   └── storage_diagnosis_log.csv  ← 진단 이력 (자동 생성)
├── .streamlit/
│   └── config.toml           ← Streamlit 테마·서버 설정
├── requirements_pdfs.txt     ← 의존성 (streamlit·pandas·numpy·scikit-learn·joblib)
├── run_hpdfs.bat             ← 일반 실행 (화면·수동진단)
└── run_hpdfs_admin.bat       ← 관리자 실행 (smartctl 자동진단 포함)
```

## 5. 인프라 담당(안세웅) 작업 범위 (수정)

```
smartmontools 설치·연동 검증
→ run_hpdfs.bat / run_hpdfs_admin.bat 실행 스크립트 관리
→ (여유 시) MLflow 실험 추적 추가
→ (여유 시) Docker 컨테이너화 (Streamlit 배포용)
```

> 초기 계획(docker-compose 5개 서비스)에서 단순화됨. 단일 앱이므로 컨테이너 1개로 충분.

---

## 6. 여유되면 추가 (순서대로)

| 순위 | 기술 | 가치 | 현실성 |
|------|------|------|--------|
| 1 | MLflow | 실험 추적·모델 버전 관리 | 설정 가볍고 포트폴리오 효과 큼 |
| 2 | Docker | Streamlit 앱 컨테이너 배포 | 1개 컨테이너라 초기 계획보다 쉬움 |
| 3 | Prometheus + Grafana | 시스템 모니터링 | 시간 여유 있을 때 |

## 7. 제외된 기술 (이유)

| 기술 | 제외 이유 |
|------|----------|
| Spring Boot | Streamlit 단일 앱으로 백엔드 역할 대체 |
| FastAPI | joblib 직접 로드로 ML 서빙 대체, 별도 서버 불필요 |
| React | Streamlit UI로 대체 |
| PostgreSQL | CSV 로그 파일로 대체 (4주 내 충분) |
| Kubernetes | 단일 앱에 과함 |
| Apache Airflow | 불필요 |
| Apache Spark | pandas로 충분 |
