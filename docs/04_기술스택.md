## 0. 선정 기준

- 판단 기준은 "멋진 기술"이 아니라 **"PDFS에 꼭 필요한가"** 다.
- 개인 프로젝트(SafeAlert)와 기술이 겹쳐도 무방하다. 꼭 필요하면 쓴다.
- 팀원 다수가 처음 쓰는 기술이므로, 학습 시간을 고려해 **코어부터 확실히** 완성하고 확장한다.

---

## 1. 꼭 필요한 코어 스택 (필수)

이 기술들이 빠지면 PDFS의 핵심 기능이 동작하지 않는다.

| 영역 | 기술 | 필요한 기능 |
|------|------|------------|
| ML 학습 | Python · pandas · scikit-learn | F-01 모델 학습 |
| 모델 서빙 | FastAPI | F-02 예측 API (Python 모델이라 필수) |
| 데이터 수집 | Python 에이전트 + HTTP 전송 | F-03 SMART 수집 |
| 백엔드 | Spring Boot (또는 FastAPI로 통합 가능) | F-04 저장·조회 API |
| 저장 | PostgreSQL | F-04 데이터·예측 결과 저장 |
| 프론트 | React + 차트 라이브러리(Recharts/ECharts) | F-05 대시보드, F-06 알림 |
| 통합/배포 | Docker + docker-compose | 5개 서비스 통합 실행 |

> **백엔드 언어 선택:** ML 서빙(FastAPI)은 Python 모델이라 고정. 일반 백엔드(F-04)는 팀 역량에 따라 Spring Boot 또는 FastAPI 중 택1. 단순화를 원하면 FastAPI로 통일, 역할 분리를 원하면 Spring Boot.

---

## 2. 여유되면 추가 (순서대로)

코어로 동작하는 제품을 완성한 뒤, 시간이 남으면 아래 순서로 추가한다.

| 순위 | 기술 | 가치 | 4주 현실성 |
|------|------|------|-----------|
| 1 | MLflow | 실험 추적·모델 버전 관리 (ML 프로젝트다움) | 셋업 가벼움 → 1순위 추천 |
| 2 | Prometheus + Grafana | 시스템 모니터링 | 인프라 담당이 빠르게 구성 가능, 팀 학습용 |
| 3 | Kafka | 실시간 수집 파이프라인 | ⚠️ 팀원 처음이면 부담. HTTP로 충분 |

---

## 3. 이번엔 제외 (4주 기준)

| 기술 | 제외 이유 |
|------|----------|
| Kubernetes | docker-compose로 충분. 4주엔 학습·운영 부담 큼 |
| Apache Airflow | 배치 자동화는 유용하나 셋업 부담 → 수동/스크립트로 대체 |
| Apache Spark | 데이터 540만 행 규모엔 과함. pandas로 충분 |

---

## 4. 인프라 담당(안세웅) 작업 범위

```
Docker로 5개 서비스 컨테이너화 (ML서빙 · 백엔드 · 프론트 · DB · 에이전트)
→ docker-compose로 통합 실행
→ 에이전트 HTTP 수집 파이프라인 구성
→ (여유 시) GitHub Actions CI/CD · MLflow 운영 · Prometheus/Grafana
```

→ "ML 시스템을 컨테이너로 묶고 모델 서빙을 배포·운영하는 인프라" 경험 확보.

---

## 5. 진행 순서 (중요)

```
① 코어 7개로 동작하는 제품 완성   (최우선)
② MLflow 추가                     (여유 시)
③ Prometheus/Grafana, Kafka       (그래도 남으면)
```

> 코어 없이 화려한 기술부터 손대면 둘 다 완성하지 못한다. 동작하는 제품이 미완성 화려함보다 항상 낫다.
