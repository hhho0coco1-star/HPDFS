01 Project Overview

프로젝트 개요

HPDFS는 클라이언트 PC의 저장장치 SMART 데이터를 수집하고, 머신러닝 모델과 규칙 기반 보정을 결합해 고장 위험도를 진단하는 시스템입니다.

핵심 문제

  • 일반 사용자는 재할당 섹터, 대기 섹터, 정정 불가 섹터, CRC 오류 같은 SMART 지표를 직접 해석하기 어렵습니다.
  • 디스크 고장은 데이터 손실로 이어질 수 있지만, 대부분의 사용자는 위험 신호를 사전에 확인하지 못합니다.
  • 단순 수치 표시가 아니라 위험도, 원인, 조치 방향을 함께 제공하는 진단 흐름이 필요했습니다.

해결 방향

  • Agent가 로컬 저장장치의 SMART 정보를 수집합니다.
  • Backend는 학습된 모델로 고장 확률을 계산하고, 주요 SMART 규칙으로 결과를 보정합니다.
  • Dashboard는 디스크별 상태, 위험도, 위험 원인, 권장 조치를 한 화면에서 제공합니다.

전체 데이터 흐름

Step 2SMART 데이터 수집
Step 3API 전송

Step 5Dashboard 조회

12 Retrospective

느낀점

프로젝트를 마무리하며 각자의 경험과 배운 점을 정리했습니다.

김응석 Data / ML

느낀점:

홍제규 Backend / DB

기계학습 모델의 성능은 알고리즘 선택도 중요하지만, 데이터 이해와 전처리 과정에 크게 좌우된다는 점을 배웠습니다. 다양한 특징(feature) 중 고장 예측에 유의미한 정보를 분석하며, 특성 선택과 데이터 이해의 중요성을 배울 수 있었습니다.

장영재 Frontend

프론트엔드를 담당하며 저장장치 상태와 AI 예측 결과를 한눈에 확인할 수 있는 대시보드를 구현했습니다. API 연동을 통해 데이터 흐름을 이해했고, 사용자 관점에서 정보를 시각화하는 방법과 협업의 중요성을 배울 수 있었습니다.

안세웅 Infra / Agent

Docker Compose로 Backend, Frontend, DB, Nginx를 단일 환경으로 묶어 팀원 간 환경 차이를 줄일 수 있었습니다. smartctl 바이너리를 레포에 포함한 결정도 도움이 되었고, 컨테이너 기반 배포가 협업 생산성에 왜 중요한지 체감할 수 있었습니다.

이성룡 Backend / DB

JS, Spring Boot가 아닌 다른 기술로 프로젝트를 구현하게 되어 많은 어려움이 있었지만, FastAPI, PostgreSQL, Docker Compose 등의 새로운 지식을 습득하며 한 단계 더 성장할 수 있는 시간이었습니다.
13 Future Plan

향후 계획

현재 구현된 로컬 Agent 기반 진단 흐름을 바탕으로, 수집 안정성, 예측 성능, 운영 기능을 단계적으로 확장할 계획입니다.

수집 안정성 개선

  • NVMe, SATA 등 장치 유형별 예외 처리 강화
  • SMART 미지원 장치에 대한 안내 메시지 개선
  • Agent 실행 상태와 전송 실패 로그 가시화

모델 고도화

  • Backblaze 데이터 추가 반영 및 재학습
  • 실제 고장 탐지율 개선을 위한 임계값 보정
  • 모델별 성능 비교와 버전 관리 체계화

대시보드 확장

  • 디스크별 위험도 추이 그래프 추가
  • 진단 이력 검색 및 필터 기능 보강
  • 위험 원인과 권장 조치 설명 개선

운영 환경 확장

  • Kubernetes 기반 클라우드 배포 검증
  • 알림 기능과 사용자 인증 기능 추가
  • 다수 PC 진단 결과를 중앙에서 관리
