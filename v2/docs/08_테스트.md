## 2. test_predictor.py — 16개

예측 로직 핵심 함수 3개를 단위 테스트한다.

### 2-1. `TestProbToLevel` — ML 확률 → 등급 변환 (5개)

| 테스트 | 입력 | 기대 결과 |
|--------|------|-----------|
| `test_정상` | 확률 0.1 | `"정상"` |
| `test_주의` | 확률 0.5 | `"주의"` |
| `test_위험` | 확률 0.8 | `"위험"` |
| `test_threshold_미만_정상` | `MODEL_THRESHOLD - 0.01` (경계값 미만) | `"정상"` |
| `test_threshold_이상_주의` | `MODEL_THRESHOLD` (경계값) | `"주의"` |
| `test_경계_070_위험` | 확률 0.7 (경계값) | `"위험"` |

> 등급 기준: 정상 `< 0.36` / 주의 `0.36 ≤ x < 0.7` / 위험 `≥ 0.7`  
> 경계 테스트는 `MODEL_THRESHOLD` 상수를 직접 임포트하여 threshold 변경에 자동 대응

## 3. test_router_diagnose.py — 5개

`POST /api/diagnose` 엔드포인트를 통합 테스트한다.
DB는 SQLite 인메모리로 대체, ML 모델은 MagicMock(`predict_proba` → 확률 0.2 고정) 사용.

### 테스트 공통 입력 (SAMPLE_PAYLOAD)

```json
{
  "serial":         "TEST001",
  "device":         "/dev/sda",
  "model":          "TEST DISK",
  "capacity_bytes": 1000000000,
  "smart_5_raw":    0,
  "smart_9_raw":    100,
  "smart_187_raw":  0,
  "smart_188_raw":  0,
  "smart_194_raw":  35,
  "smart_197_raw":  0,
  "smart_198_raw":  0,
  "smart_199_raw":  0
}
```

### 테스트 목록

| 테스트 | 확인 내용 | 기대 결과 |
|--------|-----------|-----------|
| `test_응답_필수_필드_포함` | 응답 body에 `serial`, `final_level`, `risk`, `reasons`, `actions` 포함 여부 | status 200 + 필드 전부 존재 |
| `test_등급_유효한_값` | `final_level` 값이 정해진 3가지 중 하나인지 | `"정상"` / `"주의"` / `"위험"` 중 하나 |
| `test_risk_0에서_100_사이` | `risk` 값 범위 | `0 ≤ risk ≤ 100` |
| `test_MANUAL_DB_저장_안됨` | serial = `"MANUAL"`로 진단 시 DB에 저장되지 않는지 | `GET /api/disks` 결과에 `"MANUAL"` 없음 |
| `test_모델_없을때_503` | ML 모델 미로드 상태에서 요청 시 | status 503 |
